## 實際修正

- 正式新餐期不再預填配送延遲 5 分鐘、原因 0 票或溫度 false；未收集／未觀察保留 `null`。
- 原因分為 `not-collected`、`collected`、`legacy-unverified`。已收集逐項填寫，確實沒有回覆才明確記全 0；未收集也能保存有效重量證據，不被迫捏造一票。
- 配送與溫度各自確認。0 分鐘、已觀察沒有溫度疑慮與留空不同，也不等於食品安全合規判定。
- 舊快照、草稿與備份保留原數值，缺少收集狀態時標為待複核，排除相關分析。只讀草稿不改寫原始 IndexedDB row。選單從舊紀錄轉已收集會留空重填；只有明確複核按鈕才能採用原票數。
- 草稿可保存部分票數。重新整理回到量測步驟時，仍能抵達回饋補齊，不會被後一步驗證困住。
- 決策頁揭露已收集、零回覆、未知、待複核餐數與有效回覆。無延遲觀察不顯示「最長 0 分鐘」；未收集原因不顯示「溫度 0 票」。
- 回饋／配送信心水準受該類訊號的獨立供餐日限制。五天秤重不會把一天回覆升成高信心，零回覆也不增加有效回覆日。
