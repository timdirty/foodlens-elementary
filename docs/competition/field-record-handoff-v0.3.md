# FoodLens 逐餐安全觀察回填補充 v0.3

2026-09-06。網站操作補充，非新官方提案、校方核准或已完成研究的證明。

紙本 v0.1 的 DOCX、PDF、來源台帳與原驗收保持不變。原因回饋、配送及溫度的未知值回填方式延續 [v0.2](field-record-handoff-v0.2.md)。本補充將紙本逐餐安全觀察對應到「每日紀錄」，不再把兩期總數填在一份實驗摘要中。

## 每餐怎麼記

1. 在午餐任務台保存證據鏈後，按「補記本餐安全觀察」；或在每日紀錄開啟既有餐期。先核對日期、班級、菜單與實到人數，不輸入學生姓名、學號或座號。
2. 供應不足與添餐分別選擇是否觀察。未觀察留空；確認沒有事件才填 0。已觀察時，另填本餐實際納入觀察的人數，不能直接用預計人數。
3. 缺餐回報與添餐都記「事件人次」，同一人同餐可有多次事件。跨餐比較為「每百觀察用餐人次的事件」，不是學生比例，也不代表去重人數。
4. 滿意度是另一份資料：每人每餐最多一票，填邀請人數及 1、2、3、4、5 分各級票數。所有級別都確認過後才保存；沒有該級票才填 0。
5. 確實收集而沒有任何有效回覆，才按零回覆操作。零份回覆的平均為未知，不是 0 分，更不是全班滿意。
6. 有觀察就填可找到原件的來源名稱與索引，例如匿名班級彙整表編號、頁碼。來源欄只是追溯線索，不代表系統或第三方已核驗原件。不要把個別問卷、健康或學生身分資訊上傳到來源欄。
7. 勾選確認後保存。修正要新增一版並說明理由；舊版仍在同一餐的歷史中。若另一台裝置先保存，重新讀取最新版本再核對，不會直接蓋過對方內容。

## 前後比較怎麼看

改善實驗依自己設定的日期與班級選餐，不受控制中心的全站篩選改變。每個指標分開顯示已觀察餐數、獨立供餐日、用餐人次分母、未收集和缺少紀錄的數量。滿意度由原始五級票數加權，不能直接平均每餐平均分。

同班同日同餐期有重複紀錄時，安全觀察先不合併或比較，交由人釐清；餐期人數或菜單更正後，舊觀察仍保留但暫不進比較，需新增修訂確認新條件。餐期日期、班級與餐期身分不能用 CSV 偷換。

舊版實驗摘要沒有逐餐來源與期別，只能作歷史註記，不拆成新票數或自動補入改善前後。菜單名稱組合及占比有改變時另行提示；即使相同名稱，也不代表配方、供應商或營養內容完全受控。樣本門檻只是產品提示，不是統計有效性或食品安全認證。

## 示範資料與備份

新安裝或明確重設示範資料才載入 48 筆可重現的安全觀察情境，包含未蒐集與零回覆。全部標為模擬，來源沒有真人問卷；不把這些數值當成前後介入成功的實測證明。既有瀏覽器升級不會自動回補模擬安全觀察。不要為了顯示圖表而清除正在蒐集的資料。

JSON 備份 v4 保存每筆修訂、未知狀態與五級票數。舊 v0–v3 備份缺少逐餐安全資料時，只新增空陣列，不把舊平均反推成票數。雲端需完成對應 migration 與版本檢查；本機 Demo 不依賴雲端啟用。

## 仍未完成的界線

此補充沒有新增製作量、送達量與操作計時的專用欄位；繼續按紙本另存。未取得的五源秤重也不可補 0 強行完成正式案件。正式試辦、來源真實性、營養師專業判斷、學生具名貢獻、校方核准與送件仍由真人完成。

工程結果與版本界線見[逐餐安全觀察驗收](../audits/2026-09-06-meal-safety.md)，包含本機保存、四尺寸流程、資料庫交易回滾及離線包的個別結果。尚未重製紙本 v0.1，不沿用舊檢查通過宣稱新版網站、紙本、離線包與線上部署已完全同步。
